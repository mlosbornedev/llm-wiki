# SR 6-0004564689: Golfview Developmental Center — CP5400-NS Passthrough

## SR Summary
**Customer:** Golfview Developmental Center
**Asset Serial:** 00:1C:7F:AA:D4:3B
**Appliance:** CP5400-NS (R81.20, JHF 122)
**Problem:** Customer wants to configure the CP5400-NS as a passthrough device so a new gateway behind it can manage the network.
**Product Category:** VSX/Cluster/Performance

## Problem Statement
Golfview has a new gateway that needs to be installed behind their existing CP5400-NS. They want the 5400 to act as a **passthrough** (transparent bridge/L2 mode) — no routing, no NAT, just forward traffic while the new upstream device handles all policy enforcement.

## Platform Details
- **Platform:** CP5400-NS
- **Software:** R81.20, JHF 122
- **Form Factor:** 1U rackmount, mid-range NGTX
- **Serial:** 00:1C:7F:AA:D4:3B
- **VSX:** Supported (up to 5 virtual systems)
- **ClusterXL:** Full support (HA, LS Unicast, LS Multicast, Active-Active)

## Configuration Approach
**Passthrough mode** — VSX can operate frames through without routing/NAT. This is the correct approach for:
- Transparent bridging scenarios
- Devices that need to be "in the path" without being the gateway
- Migration scenarios where existing gateway stays inline temporarily

### Relevant VSX Concepts
- VSX in passthrough: frames enter one interface, exit another without Layer-3 processing
- Virtual Switch (VSW) connects the physical ports
- See [[vsx-virtual-systems]] for VSX architecture
